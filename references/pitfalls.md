# 可复用踩坑清单

每条区分已观察的失败、处理方法与已有验证。验证记录中的模型候选代码、包内模板和实板运行是不同对象；本轮整理未修改运行代码。

## P01 Overlay

- **触发与现象**：离线查 HWH 时使用 `Overlay(download=False)` 或导入设备库；检查文件可能触发元数据/设备初始化。
- **排查与处理**：先用 `inspect_hwh.py` 和制品文件校验；板端获授权后再加载 Overlay、核对 `ip_dict` 和实际驱动。寄存器读取前先确认是否有读清除副作用。
- **来源与验证**：已有 HWH 离线正反例，PYNQ 版本依据见[开发流程](../pynq-development/references/pynq-workflow.md)。真实加载/寄存器行为需目标板证据；当前没有 `register_map` 完整教程。

## P02 Registers

- **触发与现象**：把 HLS ISR 的 TOW 套到 RTL W1C，或在读取完成状态/结果前清除它；快速 IRQ 未先注册等待者；取消后重新使用旧等待对象。
- **排查与处理**：从 HDL/HWH/头文件核对每一位的语义。先注册 IRQ 等待，再 START；按已观察待处理位确认。超时/取消后保留 unknown，控制器空闲与 IRQ 对象可复用分别判定。
- **来源与验证**：[寄存器契约](../pynq-accelerator-flow/references/register-contract.md)区分两套示例 ABI。跨题 BRAM 修复稿 CPU 检查为 8/9，取消后旧 IRQ 拒绝项返回超时，未通过；该候选问题没有在文档任务中修复。

## P03 Packaging

- **触发与现象**：在稍后调用的 proc 内用 `info script` 找源码；打包时没有添加 HDL；直接给 `bus_interface` 设置 DATA_WIDTH；再建地址块导致重叠；写入传播只读参数。
- **排查与处理**：在 source 时保存源码根目录。创建 project 后查 IP catalog，必要时 `get_ipdefs -all`；宽度/协议使用 bus parameter。复用自动推断地址块；对中断宽度/复位极性检查传播结果，逐项核准 `validate_bd_design` 的原始错误。
- **来源与验证**：[RTL 工程模板](../pynq-accelerator-flow/assets/rtl-demo/vivado/project.tcl)已有真实准备与综合记录；较早原题及本批候选的失败记录见[验证记录](validation-results.md)。这不包含所有器件/工具版本的兼容性验证。

## P04 DMA

- **触发与现象**：提交抛异常就释放，或在超时/错误后仅凭 Idle/计数不动回收缓冲；把会轮询等待的 `stop()` 当非阻塞停止请求。
- **排查与处理**：从每槽地址、cache 与 CPU/device 所有权开始；提交前移交，接收完成后同步再读，确认适用设备不再访问后才释放。停止请求、HALTED 证明和控制器可继续服务是不同条件。
- **错误恢复边界**：DMA 错误位仍置位时，即使已停机，也不能仅据此宣布设备已恢复可用。保守保留 unknown/缓冲的代码应与提前释放区分；后续恢复按实际驱动与当前授权处理。
- **来源与验证**：[生命周期例子](../pynq-dma-contract/references/pynq-lifecycle.md)是替身接口。跨题 DMA 修复稿 CPU 为 4/5：错误恢复项未满足模拟器约定，实际诊断中两槽均被保留；该项涉及保守恢复与模拟判据的分歧，不作为观察到提前释放的证据。真实 DMA/cache/错误恢复未上板。

## P05 BRAM

- **触发与现象**：功能仿真正确、代码带 `ram_style="block"`，综合后仍为 LUTRAM/寄存器；额外读地址形成不可映射的端口组合。
- **排查与处理**：画出实际读写端口、地址、时钟、使能、延迟与字节写使能；在适合的设计中先选择读地址再访问同步 RAM，或采用目标支持的 RAM 模式。通过最小综合检查实际 RAMB 原语和资源表；不只检查属性标签。
- **来源与验证**：本批 BRAM 候选综合完成，`bram_cells=0`，因此实现/导出被阻塞。私有参考最初也映射 LUTRAM；读地址修改后 727 项仿真断言通过，追加 OOC 遇临时 Tcl 读取错误，未完成物理验证。这里记录排查方法，不把该修改写成已验证的 BRAM 修复。

## P06 Reports

- **触发与现象**：报告解析器只接受带 CDC 表头的格式，将 Vivado 2023.1 的 `All paths are Safely Timed.` 简短报告判为未知；或工具报无法读取实际存在的自带脚本。
- **排查与处理**：保留原始报告/错误，区分报告格式、工具环境和设计违例。格式修正只识别有依据的语法，不改变时序/CDC/DRC/资源阈值；用现有报告复判，不因解析错误重跑综合实现。工具文件读取失败单列，按任务停止/重试额度处理。
- **来源与验证**：实验验收器在较早原题回归中补过 CDC 短格式；本批冻结前已包含该修正。**包内加速器 `gate.py` 尚未回填该兼容修正**，遇此短格式仍应保留 UNKNOWN，不能声称闭合。当前文档整理未修改该脚本。控制题首稿还曾因 Vivado 读取自带 IP Tcl 失败而阻塞，修复轮的构建独立保留。

## P07 Performance

- **触发与现象**：把累计最大值当窗口 p95；跨重连/计数回退求差；将重叠阶段直接相加；用更快的失败退出宣称成功任务加速。
- **排查与处理**：先核对样本、单位、时钟域、连接与阶段边界；按连续窗口计算，缺数据时拒绝推导。分别记录模型生成和工具执行时间，并同时报告完成状态。
- **来源与验证**：[日志格式](../stream-perf-analysis/references/log-formats.md)有正反例。本批无 Skill 均提前停止，有 Skill 执行了更多实际构建，工具耗时不用于计算成功项目的加速比。token 是 CLI 报告计数，含输入材料与缓存 token，不是账单金额。

## P08 Blocked

- **触发与现象**：IP/BD 未准备好仍要求综合；BRAM 映射不合格仍要求导出；把灰色“未执行”理解为独立测试失败。
- **排查与处理**：查第一个未通过门槛与输入产物，停止受依赖的后续阶段。分别记录 PASS、FAIL、BLOCKED/NOT_RUN；完整交付是最终判定，不是独立构建命令。
- **来源与验证**：本批三个无 Skill 项目的 T07～T10 被前置阻塞，有 Skill 的 BRAM 项目 T08～T10 被映射门阻塞。[包内逐项数据](evidence/cross-task-checks.csv)保留原始 NOT_RUN，并用独立列显示 BLOCKED；评分仍按原定义“已通过任务数/10”，不是“已执行项通过率”。

详细统计、方法、已知判据分歧和原始记录索引见[验证记录](validation-results.md)。
