# FPGA 分层验证与证据边界

用于一个具体硬件问题；不是每次软件修改的默认构建流程。输入包括实际源码/参数、触发条件、当前制品和可证伪判据。可用 [验收模板](references/acceptance-template.md) 记录相关层，未涉及的层不必填满或运行。

## 使用方法

1. 先明确问题和通过条件，例如 AXI 停顿后字节是否完整、RAW10/BGGR 到 DDR 的顺序是否正确、复位是否丢 SOF、当前 BIT/XSA 是否与运行软件配套。
2. 查实际源、参数、约束和构建入口，先静态/语法、最小仿真或 host 黄金对照；已有检测/算法保持唯一入口，不为验证复制第二套实现。
3. AXI 流核对握手接受的 SOF/EOL/TLAST、TKEEP、背压时保持、连续帧和复位边界。计数对象必须是被接受的事件；“看到 720 个包”不自动等于“输出 720 行有效视频”。
4. Bayer 核对 RAW 位打包、BGGR 相位、裁剪/翻转奇偶、DDR 字节顺序；不能靠下游交换颜色把上游错误隐藏。
5. 只有较便宜检查不能回答时才进入 OOC/完整实现，并沿当前任务授权执行。实现结果保留当前配置的时序、未约束路径、CDC、DRC 和资源；负 slack、未解释 CDC 不转签 PASS，不添加无依据例外。
6. 输出输入身份、层次、判据、实际结果和未覆盖范围。保留 FAIL / NOT_RUN / UNKNOWN / NOT_PROVEN；旧 OOC、单模块通过、截图或旧制品不能证明当前顶层实时闭环。

## 可复制提示词

```text
使用 $fpga-verification-gates。当前改动/阻塞：填写具体触发与期望。
输入：canonical RTL/参数/XDC、构建入口、实际报告或原始日志。
先设计能证伪当前假设的最低成本检查，再决定是否需要实现或实板。
区分静态、host 模型、RTL 仿真、OOC、生产顶层和实板证据；不把未运行层写成通过。
输出一个主要结论、证据位置和最小下一步。
```

## 复用示例与失效条件

场景：CSI 报告 CRC0，但显示偶发短帧。先问计数是否属于同一失败帧、是否记录被接受的视频行；“719 行且 CRC0”是足以推翻 CRC0⇒完整帧的反例。优先在同一窗口关联 SOF/EOL/行数，不能直接归因于 PARK，也不必立即改 PHY 或全量重建。

没有原始失败采样、实际配置/构建来源不明，或只有清理后的寄存器时，根因仍是 UNKNOWN。host 模型能证明推理反例，不能证明真实 RTL 发出了该序列。当前工程的现有路径见 [工程适配](../references/project-context.md)；其他团队替换器件与验收预算，不照搬项目数值。

## 经验来源与已验证效果

历史工程曾在 719 行/CRC0 与 720 CSI 包/719 视频行的 host 反例中拒绝错误的“帧完整”结论，并把首错记录放在清理前；差分检查确认诊断改动未改变既有寄存器访问序列。历史记录见 [project-evidence.json](../references/project-evidence.json) 的 `validation`、`safety`。本轮只维护方法和模板，没有运行 RTL/Vivado 或重新验收原硬件。
