## 完整技能包实验设置（文件工具可用时）

- 主对照为 baseline（不启用技能）与 skill（启用本技能及分析脚本）。两组使用相同模型、推理设置、工具、原始输入、任务提示和预算。比较的是完整技能包的效果，不能单独归因为提示词改进。
- 使用 [任务](tasks.md) T1/T2/T3，各组每题3次，共18次。每次新会话；仅提供本题原始输入与通用字段说明。默认每次10分钟、最多20次工具调用，先到即停；不得为某组追加预算。模型上下文等其他限制固定并记录。
- baseline 只能访问任务输入和相同的通用工具；skill 额外获得 SKILL.md、scripts 和必要格式参考。不提供本目录、讲解、已有示例/测试答案或原工程历史。组织者需在工作区外隔离这些文件；仅要求执行者“不读取答案”不足以防泄漏。
- T1/T2 的两组均获得字段含义与 pipeline 包含 sample 的说明。skill 组使用额外指令：“按随附 stream-perf-analysis/SKILL.md 分析”。禁止两组自动加载其他项目 Skill 或 AGENTS，保持全局约束一致。无法隔离时在记录中说明混杂，不声明严格对照。
- 每个任务按 baseline/skill、skill/baseline、baseline/skill 的次序交替运行3对。记录缓存状态，不把复用旧回答当新实验。选择性重跑必须保留原记录和原因。
- 评分者在答复完成后使用 [评分标准](graders.md)，先隐去组别再评分。任务成功要求4/4且无硬失败。执行者看过答案或评分标准的运行无效。

已完成的文本变体：原始数据直接放入提示词，两组禁用工具、全局技能发现、项目说明及记忆；技能组仅额外获得SKILL.md与格式说明，不提供脚本源、案例讲解或评分答案。每组每题3次，沿用交替顺序及600秒上限。实际评分由当前助手本地按规则审阅，未使用独立盲评者；缓存命中、服务排队和启动开销均可能影响耗时。

## 记录与统计

复制 [空白 CSV](runs.csv) 到技能包外的实验输出目录，每次试验一行，保留回答、工具轨迹、评分依据和平台用量记录。版本用五项文件（SKILL.md、analyze.py、log-formats.md、任务文件、评分文件）的 SHA256 或包含这些文件的提交号标识；实验输入另记哈希，不用含未提交修改的 HEAD 冒充版本。

`elapsed_s` 为提交任务到执行者最终答复的墙钟时间，含工具和自主修正，不含事后评分。截止时未完成仍保留全部已耗时间。它不是“到最终验收通过”的耗时；人工返工后重测需另开记录。`human_interventions` 记录执行中纠正方向、补信息或直接代改的次数；任何实质干预会使该次不满足独立运行条件，标记 invalid 并保留轨迹。

Token 使用平台累计用量，包含技能加载、输入/工具回传、输出和重试；不把每轮累计快照再次求和。`input_tokens` 含缓存输入，`cached_input_tokens` 是其子集；`output_tokens` 按平台口径，推理 Token 若是其子集不重复相加。无法获取记 NA；对话字数不能替代 Token。使用不同口径的平台记录不能直接合并。

`status` 为 completed、timeout、budget_exhausted 或 invalid。`success` 为1/0，invalid填NA；`score` 为0..4。`hard_failure` 为1/0；预算耗尽和超时计入失败。Token 缺失只排除成本统计，不排除结果统计。

- 成功率：成功次数/有效次数，展示原始计数；invalid另列。
- 耗时与Token：按题、按组展示每次点及中位数。成功运行的比较同时展示成功率；失败消耗另列，不把提前放弃当效率提高。
- 单位成功任务Token成本：有效试验全部输入+输出Token之和/成功次数；无成功为未定义，用量缺失时不计算完整成本。
- 每组每题仅3次，展示小样本结果，不作显著性结论。节省比例须在相同任务和统计口径下计算。
