# 实物交互与权威场景集成

适用于摄像头观测驱动交互、模型与求解结果必须一致的系统。复用已有检测、稳定器、求解器、状态机与唯一配置；新建并行检测器或第二个通关判定器会破坏同一场景的语义。

## 使用方法

先明确本次改动属于观测、稳定、提交、权威计算还是呈现，再读取相应代码与最小观测样本。当前仓库的实际入口和参数见 [工程适配](../references/project-context.md)；其他项目用自己的入口替换，不照搬阈值或尺寸。

1. 明确坐标空间、物体身份、中心/有向轴和有限有效边界。相机像素、棋盘毫米和显示像素需要明确变换；未标定时只报告像素精度。固定发射条件属于关卡配置，不伪装成摄像头 SOURCE 观测。
2. 沿原始 generation、sequence、captured time、level、质量和时钟域追踪一份输入。跨设备使用映射区间；接收时间不是采集时间，处理开始也不自动等于曝光时间。
3. 稳定器只在一个位置提交。按实际支持间隔区分新确认、PENDING、缺失、受限和 HELD/STALE；位置或角度变化都能触发更新，不能要求“移动后才能旋转”。有向 Portal 与 180° 等价 Mirror 的角度处理分别核对。
4. 一次替换物体模型和完整光段。呈现缓存保留原始标记，不能回送权威核心当作新鲜观测。显示时限、稳定支持间隔、场景准入和校时质量是独立参数。
5. 找出本局唯一权威会话。两个前端复用同一个核心不等于两屏已经共享同一局结果；若板端只是诊断光路，不声称与 PC 同局结算。界面只发送操作请求、呈现结果与装饰效果。

## 几何与生命周期检查

- Mirror 为有限反射面；Portal 只在定义的长侧入口传送，出口策略与有向轴、法向绑定；Target 使用明确命中边界。bbox、颜色外框或标签外框不自动等于有效边界。
- 检测 profile 决定标记语义。当前工程使用彩色旧标记，不启用 AprilTag；迁移项目如果真的使用多标签，则按实测刚性模板联合可见角点拟合并保留残差，不只平均中心。
- 切关、菜单、结束、重连、旧序号和旧会话分别处理；关卡操作以匹配的确认与身份为准，不以 UI 强制解锁绕过协议。
- 粒子、反射火花和 Portal 特效只消费有效事件；终止点后不续画，Portal 两端间不补实线，陈旧场景不产生命中特效。

## 可复制提示词

```text
使用 $ray-game-integration。目标工程：填写仓库/模块；本次问题：填写触发与期望。
提供：实际配置、检测/稳定/权威核心/界面入口、一段带原始帧标记的输入。
先找出唯一权威提交点和时钟/坐标契约，再完成本次必要修改。
沿用当前已授权阈值与 profile；只验证相关的移动、原地旋转、遮挡、旧关卡和原子替换。
输出：改动、可复现检查、已验证范围和剩余问题。
```

## 失效条件与最小验证

没有原始采集标记、无法区分有效与显示保留、入口几何不明或跨设备时钟无依据时，不能判定实时正确。优先用同一输入的 host 回放验证：旧帧不能得分，新完整场景整体替换，旋转出口随物体转动，擦边遵守有限边界。改到 ARM 代码再编译；真实板端结论需要真实输入，技能本身不授权连接硬件。

## 经验来源与效果

工程曾出现板端 Portal B 已用正法向出口、PC 仍用旧配对出口的问题；修复复用了同一个策略求解入口，历史用例覆盖双入口侧与四种旋转。遮挡时虚拟物块消失的问题通过保留整份已接受场景解决，原时间不变且不回送 C；host/Godot 用例覆盖陈旧命中不得分、重连保持及切关清理。证据摘录见 [project-evidence.json](../references/project-evidence.json) 的 `pc_portal_b_alignment_perf_20261028`、`pc_continuous_scene_20261028` 和 `web_sync350_20261028`。这些是原工程历史结果，本轮未重跑整个游戏。
